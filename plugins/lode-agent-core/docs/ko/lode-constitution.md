# 공급자 중립적 Lode 헌법

> 영어 원문: [`../lode-constitution.md`](../lode-constitution.md)

## 목적

Lode Agent Core는 컨텍스트 손실, 공급자 교체, 선택적 worker, 교체 가능한 스토리지에도 하나의 일관된 프로젝트 방향을 보존합니다. 이를 위해 작은 규범적 헌법과 타입이 지정된 내부 강제 체계를 사용합니다. 메커니즘은 보호해야 할 결과에 종속됩니다.

## 규범적 규칙

1. **일관된 프로젝트 방향.** 하나의 정식 Project에 공통 사용자 방향과 독립적으로 라우팅되는 여러 논리 Lode Session이 있습니다. 각 Session은 목적, 진행, 활성 작업과 복구를 별도로 보존합니다. 공급자 세션, 창, 프로세스 및 모델 호출은 교체 가능한 소비자입니다.
2. **직접 작업이 기본입니다.** Lode는 일반적인 작업을 일관되게 처리합니다. 위임은 범위가 한정되고 독립적으로 검토 가능한 전체 결과가 있을 때만 정당화됩니다. 병렬 처리는 범위나 권한을 만들지 않습니다.
3. **복구의 소유자는 아티팩트입니다.** 계획, 계약, 체크포인트 및 정확한 참조가 방향을 보존합니다. 요약과 트랜스크립트는 사람이 상황을 파악하는 데 도움을 줄 수 있지만 복구 상태를 다시 쓸 수는 없습니다.
4. **출력은 증거입니다.** worker 결과, 런타임 이벤트, 메시지, 저장소 관찰 및 외부 검토는 검토 가능한 증거로 남습니다.
5. **뷰는 교체 가능합니다.** 그래프, 인덱스, Markdown, Context Capsules 및 연속성 스냅샷은 권한을 지닌 레코드와 증거 레코드를 재현 가능하게 소비합니다. 편의상 유일한 진실이 될 수는 없습니다.
6. **권한은 명시적입니다.** Product Canon은 정확한 현재 후보 집합을 범위로 삼아 사용자가 작성한 ReviewDecision을 통해서만 변경됩니다. 실행 성공, 모델 간의 동의 및 작성자 피드백은 승인을 의미하지 않습니다.
7. **공급자 중립성은 기능 대칭성이 아니라 의미 체계를 보존합니다.** 각 어댑터는 스스로 입증할 수 있는 기능만 노출할 수 있습니다. 누락된 선택적 기능은 공개되며, 공급자별 런타임을 모방하기 위해 Core 계약을 약화하는 일은 없습니다.

## 프로필

공개 초기화 트랜잭션에는 두 가지 프로필이 있습니다.

- `core`가 기본값입니다. Project/Session 앵커와 공급자 투영을 보존하고, 그래프 탐색을 위해 적격한 기존 관측 자료를 색인화합니다. 제품 의미 추론, Canon 승격, 전체 World 구성과 관리 문서는 선택 사항입니다.
- `product`는 증거가 연결된 온보딩과 검토 게이트가 적용되는 Product/World/Graph 경로를 명시적으로 시작하거나 재개합니다.

product 프로필은 선택적 거버넌스 기능이지 Lode 자체의 정의가 아닙니다. core 재개는 기존 product 상태를 새로 고치거나 승격하지 않고 보존합니다. `product`를 명시적으로 선택하지 않은 채 온보딩 입력을 제공하면 fail-closed 방식으로 실패합니다.

프로필은 영구 모드가 아니라 작업별 선택입니다. 읽기 전용 준비 상태 프로젝션은 Core와 Product 상태를 설명하고 다음 작업을 권고하며 선택적 기능의 전제 조건을 공개할 수 있습니다. 이 프로젝션에는 권한이 없습니다. Product를 활성화하거나, 실행 리니지를 생성하거나, 권한을 부여하거나, 드리프트를 복구하거나, 복구 방향을 기록할 수 없습니다.

## 레코드와 그래프 경계

그래프는 권한 아티팩트와 증거 아티팩트에 *관한* 출처를 기록할 뿐, 권한 레코드 자체가 되지는 않습니다.

| 관심사 | 영속적 소유자 | 그래프 또는 문서의 역할 |
| --- | --- | --- |
| 승인된 제품 의미 | Product Model revision + ReviewDecision | 프로젝션 및 감사 추적 |
| 공통 방향과 독립 진행 | ProjectDirection + 선택된 Session/Run pointers + checkpoint | 참조되는 복구 뷰 |
| 실행 결과 | ResultPacket + review lineage | 증거 순회 |
| 저장소 관찰 | SourceSnapshot and immutable revisions | 범위가 한정된 탐색 |
| 호스트 효과 | lease, PID, endpoint, delivery receipt | 운영 증거로만 사용 |

그래프, 데이터베이스, Markdown 뷰 또는 캐시가 사라지더라도 시스템은 정식 레코드와 증거로부터 복구 가능해야 합니다. 뷰 재구축이 ReviewDecision을 생성하거나, Session을 진행시키거나, 권한 부여를 소비하거나, 호스트 효과를 주장해서는 안 됩니다.

## 컴팩션 연속성

관리형 컴팩션 lifecycle을 선택한 경우에만 불변 체크포인트 준비, 공급자 압축, 신뢰된 실제 사용자 턴 검증, 일회성 연속 토큰 소비의 네 단계를 적용합니다. 일반 native 컴팩션과 startup은 충분한 기존 맥락을 재사용하거나 읽기 전용 conversation entry로 복구합니다. 체크포인트가 없어도 일반 직접 작업과 Host 위임은 계속하며, 파일 수정·worker 수·일반 실패만으로 관리형 lifecycle을 요구하지 않습니다. 복구 앵커는 `.lode/project.json`, 선택한 논리 Session 기록과 정확한 체크포인트입니다. `.lode/sessions/current.json`은 기본 Session으로 유지되고 다른 Session은 `.lode/sessions/by-id/<session-id>/current.json`을 사용합니다. 복구와 함께 현재 공통 ProjectDirection을 읽습니다. 과거 체크포인트 필드는 그대로 보존하되 더 최신인 공통 제약이나 취소된 작업을 되돌리지 않습니다. 공급자 요약은 앵커로 승격되지 않고 새로운 사용자 턴이 준비된 연속 작업보다 우선합니다.

## 그래프 우선 탐색과 실행 선택

새 프로젝트 정보는 제한된 그래프 조회 또는 충분한 동일 기준 결과 재사용으로 찾습니다. Lode 작업과 Product는 공통 원본의 논리 관점입니다. 리비전, 출처, 확인 범위와 원래 후보·거절 상태를 온전한 과거 자료에도 표시합니다. 자료 부재나 조회 실패는 원본 탐색으로 이어지며 전체 준비도 gate가 되지 않습니다. 전체 World current, Product 승인, 색인 완료, Run/Capsule, DB 연결은 일반 탐색의 선행 조건이 아닙니다. 손상된 층만 제외하고 실제 변경은 현재 원본과 권한을 다시 확인합니다.

직접 작업, 일반 Host 위임과 관리형 실행은 필요한 결과에 맞게 선택합니다. 지속 소유권, 중단 복구, 불명·중복 효과 관리에 관리형이 유용하지만 파일 수정, worker 수, 일반 실패만으로 강제하지 않습니다. Fork/fresh는 별도 맥락 선택이며 승인, 격리나 cache를 보장하지 않습니다. 완료된 기여는 보존하고 결과 불명 효과를 확인한 뒤 대체하며 독립 작업은 계속합니다.

의미 있는 코드 수정이나 기능 작업 뒤에는 Lode가 통합 결과의 그래프 갱신 필요를
확인합니다. 목적, 구현과 실제 검증을 원본 기록에 연결하고 필요한 지원 관계를
갱신하며, 미확인·미투영 범위를 남깁니다. 그래프 투영이 의미, 승인이나 복구 방향을
만들지는 않습니다. 충분히 최신인 기존 갱신은 재사용하며 매 턴 전체 갱신,
World/DB 활성화, 새 Run/Capsule, watcher나 일상적인 사용자 승인을 강제하지
않습니다. 갱신 실패는 해당 증거의 미반영 범위로 남기고 현재 원본 보완과 독립 작업은
계속합니다. [그래프 갱신](graph-discovery.md#통합-변경-뒤의-증거-갱신)을 참고하세요.

## 적합성 테스트

확장은 다음 질문 모두에 예라고 답할 수 있을 때만 적합합니다.

- 공급자 구성 요소를 교체해도 Project와 Session이 존속할 수 있는가?
- 선택적 Product/Graph 메커니즘 없이도 보호 대상 결과가 동작할 수 있는가?
- 모든 권한 전이가 명시적이고 범위가 지정되어 있으며 재실행에도 안전한가?
- 의미나 방향을 꾸며내지 않고 모든 파생 뷰를 재구축할 수 있는가?
- 선택적 어댑터를 사용할 수 없을 때 Core를 약화하는 대신 기능 손실을 공개하는가?
- worker 및 호스트 효과가 정확한 ID, 소유권 및 정리 증거로 한정되는가?

강제 가능한 상세 매핑은 [`authority-plane-contract.md`](authority-plane-contract.md)에 있습니다.

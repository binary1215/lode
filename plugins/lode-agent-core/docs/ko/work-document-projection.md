# Notion·Obsidian 작업 문서

[English](../work-document-projection.md)

선택한 작업을 문서로 정리해 달라고 요청하세요. 같은 정확한 원기록에서 사람용 설명과
에이전트용 Markdown을 만듭니다. 이유·대안·조건·결과·남은 일·미확인을 함께 제공합니다.
새 사용자 승인·Product Canon·체크포인트·완료 판정이 되는 문서는 아닙니다.

로컬 미리보기에는 Product 온보딩·World 재구축·내보내기·Run·Todo 도입이 필요하지
않습니다. Todo 없는 기존 작업도 정확한 원기록과 명시적 작업 연결로 선택합니다.
도구 인자는 Lode가 채우므로 사용자가 JSON을 작성할 필요는 없습니다.

연결할 때 vault나 Notion 부모 페이지와 자동 갱신할 태스크 범위를 지정합니다.
연결 자체는 게시하지 않습니다. Notion은 명시적으로 선택한 Host 환경 변수 참조만
저장하며 토큰 저장·주변 자격증명 탐색을 하지 않습니다. 미연결이 일반 작업을 막지
않습니다. 실제 게시에는 현재 유효한 목적지·내용 범위의 사용자 권한이 필요합니다.

## 결과 읽기

### 제품·기능별로 프로젝트 탐색하기

“프로젝트 문서를 제품 → 기능그룹 → 기능 순서로 정리하고 사람용·에이전트용을
만들어줘”라고 요청하세요. 실제 제품 모델의 소속을 사용하며 중첩 그룹과 여러 부모를
모두 유지합니다. 여기서 제품은 기존 Project의 읽기 루트이며 새 정본 엔티티가 아닙니다.
여러 기능의 결정·작업은 같은 원문으로 연결하고 세션을 한 기능 아래에 가두지 않습니다.
확인되지 않은 소속은 미분류로 남깁니다.

두 뷰의 사실은 같습니다. 사람용은 목적·흐름·조건·결과와 유용한 링크를, 에이전트용은
정확한 ID·원문·선택한 코드·diff·그래프 근거도 제공합니다. 설명은 HEAD가 선택한 정확한
원문에 연결합니다. Core는 의미나 구현 관계를 추론하지 않습니다. 인용한 원문은 고정되며
제품 모델이 바뀌면 과거 설명임을 표시합니다. 코드·비교·실행 증거가 없으면 미확인입니다.

기존 연결 대화에서 선택적 projectDocuments 범위를 지정합니다. 업데이트가 작업별 게시
권한을 프로젝트 전체로 넓히지 않습니다. 사용자 JSON·Todo·온보딩 절차를 추가하지 않습니다.
명시적으로 자동 갱신을 선택한 프로젝트는 Todo 없는 분석 결과도 문서화합니다. 기존의
풍부한 근거 선택은 HEAD가 유지하거나 의식적으로 수정하며 최근 메모 하나로 몰래 축소하지
않습니다.

같은 실제 Notion 부모나 물리 vault의 다른 연결 별칭·세션은 프로젝트 홈을 공유합니다.
제목이 같은 다른 프로젝트는 분리합니다. Notion은 선택 부모 아래 프로젝트 홈과 독자 홈·
항목 페이지를 만들며 각 자식의 정확한 부모를 검사합니다. Obsidian은
Lode/<Project>/ProjectDocuments/에 추가합니다. 기존 작업 문서는 이동·삭제하지 않습니다.
이름이 바뀌어도 페이지 ID는 유지하고 이전 본문은 이력으로 연결합니다. 개인 메모는 갱신하지
않습니다.

65번째를 넘는 문서도 제한된 게시 호출을 이어서 처리합니다. continuation-required는
HEAD가 이어갈 일이며 사용자 스크립트 실행·작업 재저장이 아닙니다. 선택한 모든 페이지와
필수 링크를 관측한 뒤에만 게시 완료를 보고합니다. **동시 원격 CAS를 보장하지 않으며**
receipt는 마지막 확인 범위입니다. 원문·설정 변화나 사용자 편집은 이전 current receipt를
보존합니다. 미조회·미선택 세션을 삭제로 해석하지 않으며 잘못된 Canon이나 접근 거부를
빈 제품으로 낮추지 않습니다. 후속 갱신은 자식 본문을 바꾸기 전에 홈 맨 위에 진행 중·
미확정을 표시합니다. 링크가 서로 다른 갱신 시점으로 이어질 수 있음을 알리고, 선택한
전체 게시를 관측한 뒤에만 표시를 해제합니다. 실패·취소 후 혼합된 범위를 조용히 완료로
보이지 않습니다.

생성 응답 유실 뒤의 검색이 여러 호출로 나뉘면 일치 페이지도 관측 후보로 남깁니다.
서로 다른 시점의 구간을 합쳐 현재 전체 유일성을 증명하지 않습니다. 이 한계는 재시작·
원문 변경·연결 별칭 변경 후에도 해당 시도에 남습니다. 후보 재조회는 본문 변화·조회 시점의
부재·조회 실패를 구분하지만 자동 연결이나 POST 재전송의 근거는 아닙니다. 정확한 provider
terminal 결과 ID의 기존 복구는 별도로 검증합니다. 단일 제한 조회 역시 원격 원자
snapshot이나 최초 저자 증명이 아닙니다.

Typed MCP는 lode_project_document_prepare, lode_project_document_publish,
lode_project_document_status, CLI는 project-document-prepare,
project-document-publish, project-document-status입니다. 정확한 작업 참조·기능 읽기
연결·기존 코드/diff 선택·설명문 인자는 HEAD가 채웁니다.
document-projection/project/<Project>/의 P5 게시 상태는 세션 P2 방향을 합치지 않습니다.

안정적인 Lode 전용 시작 문서에서 마지막으로 확인한 사람용·에이전트용 뷰, 별도
개인 메모, 이전 게시 문서로 이동합니다. ‘현재’는 두 뷰와 필수 링크를 readback한
마지막 근거입니다. 미게시 로컬 변경 전체·태스크 완료·배포 완료·모든 원문의 최신성을
뜻하지 않습니다.

중요한 취소·미실행 검사·모순은 양쪽 뷰에 동일하게 남깁니다. 작성자의 합의 요약은
실제 사용자 발언이 아닙니다. 해시 일치는 의미상 최신성을, 과거 검사 통과는 현재
코드의 검사 통과를 뜻하지 않습니다. 실제 전후 바이트가 있을 때만 제한된 비교를
제공하며 없으면 diff 미확보를 표시합니다. 그래프 관계는 탐색에 쓰고 승인·구현
충족·인과로 바꾸지 않습니다.

선택 내용과 비교 자체는 문서 안에서 읽습니다. 로컬 경로는 근거 식별자이며 원격
독자에게 열리는 링크로 보장하지 않습니다. 전체 대화·provider 세션 ID·로컬 절대
루트를 자동 복사하지 않습니다. 다른 태스크일 수 있는 Session 체크포인트 전체도
자동으로 내보내지 않습니다.

## 자동 갱신·재시도

비동기 CLI/MCP `session-work-record` 조합은 기존 create-only P3 원문부터 저장합니다.
명시적으로 연결한 단일 범위 태스크 결과이면 관련 문서를 준비합니다. 이후 partial·
waiting·cancelled·정정도 갱신합니다. 앱 종료·idle·체크포인트 저장·빈 pending·단독
`completed` 표기는 완료 근거가 아닙니다. 혼합 태스크나 불완전·충돌 revision은 게시만
미확정으로 두며 작업 저장은 유지합니다. 변화 없는 재시도는 중복 문서를 만들지 않습니다.

동기 `recordSessionWorkEvidence` API는 동기입니다. 체크포인트 sync와 무관한 저장에는
외부 게시를 추가하지 않습니다. 단일 Todo 없는 작업은 명시 생성할 수 있으며 필수
Todo·저장 의식으로 바꾸지 않습니다.

동일 결과 재시도는 확인한 근거·diff·인용·관련 기록·그래프 선택을 재사용합니다.
최근 기록 하나로 몰래 축소하지 않습니다. 새 revision에서는 같은 비동기 record 호출에
선택적 `document_selection`을 함께 전달할 수 있습니다(CLI `--document-selection`).
그 요청의 `recorded` 별칭은 저장된 정확한 원문으로 해소하며 P3 스키마나 권한을
바꾸지 않습니다. 기존 풍부한 범위를 HEAD 판단 없이 안전하게 이을 수 없다면
`head-selection-required`, 기록된 재개·취소, 원격 미갱신 상태를 반환합니다. HEAD가
제공된 정확한 이전 범위를 참고해 같은 턴에서 명시적 준비·게시를 끝냅니다. 사용자
양식이나 작업 재저장을 요구하지 않습니다. 이전 before/after는 새 기록의 선택으로
명시하지 않는 한 과거 비교이며 새 변경으로 자동 재해석하지 않습니다.

실질적인 분석 결과 글은 유효한 P3 본문만으로 게시할 수 있으며 외부 파일 첨부가
필요하지 않습니다. 태스크명·상태만 있고 결과 내용이 없으면 미확정입니다. 이는 내용의
존재 확인이며 의미적 충분성·실행 성공·승인 판정이 아닙니다. 원문 파일이 없으면 두
뷰에 정확한 실패 코드를 남기고 보존 바이트와 현재 파일을 구분합니다. 불가능한 비교와
인용은 unknown으로 유지합니다. 원본 P3 소유·digest 실패는 근거 검증 실패이며 원문
접근 거부를 다른 reader로 우회하지 않습니다. 텍스트 전용 CLI/MCP 응답에도 구조화
응답과 동일하게 게시 상태와 HEAD의 제한된 준비·게시 후속 작업을 전달합니다.
문서 게시 효과와 원래 작업 효과를 구분합니다.

효과 전에 시도 기록을 저장합니다. 생성 응답 유실은 그 기록과 선택 부모의 제한된
목록에서 본문·부모를 정확히 대조합니다. mapping 유실·복사 표식·중복 일치·task 만료·
빈/부분 목록은 POST 재발행 근거가 아닙니다. 일치 사본도 최초 생성 사건·저자 권한의
증거가 아닙니다. 과거 exact ref를 같은 제목의 새 페이지에 연결하지 않습니다.
알려진 async task는 terminal 성공과 readback을 요구하며 warnings 부재만으로 성공
처리하지 않습니다. 한 목적지 실패는 다른 목적지 receipt를 지우지 않습니다. 게시만
재시도하고 원래 작업 효과는 다시 실행하지 않습니다.

Notion 페이지 생성·정확한 Markdown 교체에서 정상적으로 일치하는 `403` /
`restricted_resource` 응답은 결과 불확실과 구분해 요청 거부로 기록합니다.
이 코드는 권한 부족뿐 아니라 workspace 블록 한도일 수도 있어 원인을 그대로 남깁니다.
원인을 고쳐도 자동 재시도하지 않습니다. 현재 권한 범위 안에서 HEAD가 반환된 정확한
시도 참조를 `retry_rejected_writes`(CLI 입력 `retryRejectedWrites`)에 전달하면 동일
요청의 후속 시도 한 번을 만듭니다. 이전 시도·결과는 create-only로 보존합니다.
다시 거부되면 새 참조가 필요하며 중복 클릭은 후속 시도를 추가 생성하지 않습니다.
부모·method·내용·설정·원문 근거·현재 관리 본문이 여전히 일치해야 합니다.
원문이 바뀌면 HEAD가 새 문서 쌍을 준비합니다. 시작/메모 문서의 생성 요청 자체가
완전히 같다면 확인한 새 근거에서도 이전 거부 참조를 이어 쓸 수 있습니다.
과거 뷰·바뀐 쓰기 본문·오래된 준비 근거를 재사용하는 것은 아닙니다.
사용자 JSON이나 원래 작업 재실행을 요구하지 않습니다. Host 거부 우회·다른 계정 전환·
자동 record hook에서의 묵시적 재시도는 허용하지 않습니다.

HTTP 숫자·오류 문구·호출자 플래그만으로는 판정하지 않습니다. 비정상·불일치 오류,
응답 유실·5xx·async 실패·시간/용량 제한·거부 증거 저장 실패는 결과 불확실이며 새
쓰기를 허용하지 않습니다. 재시도 응답이 유실되어도 같은 readback 전용 복구를 따릅니다.
거부 기록은 P5 운영 증거이며 실행 허가나 복구 방향 결정이 아닙니다.

Notion 게시·복구 한 번의 전체 예산은 30초·64요청이며 응답은 수신 중 4MiB를
제한합니다. 의미적 컨텍스트나 일반 작업 제한이 아닌 선택적 전송 예산입니다.
소진되면 효과를 미확정으로 보존합니다. 상주 daemon 없이 다음 요청에서 알려진
대기를 이어갈 수 있습니다.

## 소유·동시 편집

작업별 모드의 Obsidian은 선택 vault의 `Lode/<Project>/<Session>/<task-key>/`만 씁니다. revision은
exclusive create하고 개인 메모는 분리합니다. 관리 영역은 정확한 이전 본문이 유지될
때만 바꿉니다. Notion도 전체 교체 대신 단일 `update_content` 정확한 문자열 교체를
합니다. 관리 밖 내용은 보존하고 생성 뷰 편집은 drift로 표시하며 덮어쓰거나 정본으로
수집하지 않습니다.

목적지별 로컬 조정은 HTTP 중 Project mutation lock을 잡지 않습니다. 사전·사후 조회와
정확한 문자열 교체는 **원격 CAS가 아닙니다**. 임의 동시 편집의 무손실이나 두 목적지의
원자 게시를 보장하지 않습니다. receipt는 실제 확인 범위와 부분·미확정을 남깁니다.

## API·시험

Typed MCP는 `lode_work_document_configure`, `lode_work_document_prepare`,
`lode_work_document_publish`, `lode_work_document_status`이고 `lode_work_` 그룹에서
찾습니다. CLI는 같은 `work-document-*`와 요청별 Session 경로를 제공합니다.
status는 로컬 receipt이며 실시간 네트워크 최신성 검사가 아닙니다.

공통 근거·뷰는 P4, 설정·시도·async 진행·receipt·교체 가능한 current 포인터는 기존
`document-projection/work/<Session>/`의 P5입니다. 논리 키·근거·렌더 뷰·링크 해소
payload·readback 해시를 구분합니다. 기존 동기 GraphSnapshot Markdown 바이트 일치

# Session work context and Host continuity

[한국어](ko/session-work-context.md)

Ordinary investigation and direct edits need neither a Run nor a save ritual.
Lode preserves useful context at a meaningful handoff or context-loss boundary,
then the same logical Session's entry reconstructs selected original records.
This is not transcript recovery or a guarantee that unsaved conversation survives.

## What is preserved, and by whom?

Current common direction belongs to ProjectDirection. Session-local purpose,
constraints and cancellations stay in explicit Session P2 direction: the existing
Session purpose and latest checkpoint, not a shared Project update or P3 memory.
For example, a Session can retain “investigate locally, no network” in its purpose
and explicit decisions, then replace an earlier rewrite proposal with “rewrite
cancelled; explain only” in its current checkpoint. A sibling Session is unchanged.
Lode authors and interprets this text; Core does not extract approval from words.
Historical decisions and next steps never grant current execution permission.

Reuse existing checkpoint, result, review and source originals first. Only
otherwise unrepresented reasons, rejected alternatives, selected observations,
pending work and uncertainty need a small Session-owned P3 Evidence original.
Its historical suggestions cannot populate recovery fields or approve work.
The new record has a distinct subtype under the existing Evidence plane, not a
second direction store, history document, global memory database or daemon.

## A light preservation path

- When checkpoint synchronization is already useful, Lode includes optional
  `work_evidence` in the existing `lode_checkpoint_sync` request. P2 and P3
  have separate outcomes. A stale/deferred checkpoint does not promote its
  retained work evidence; an optional evidence-storage failure does not block
  an otherwise valid explicit P2 publication.
- Without a useful checkpoint boundary, one optional `lode_session_work_record`
  preserves selected Run-free context. Lode supplies sparse input from the
  conversation. The user need not author JSON, choose an ID, approve saving,
  create a Run or compile a Capsule.
- `lode_conversation_enter` reads selected Session originals and existing P2
  direction, together with current common constraints/cancellations. It writes
  nothing. Missing or damaged optional evidence affects only that layer.
- `lode_session_work_read` expands known exact originals or an explicitly anchored
  ID inspection page. Use it when needed, not as a compulsory tool chain.

Already saved work also appears in existing `lode_project_graph` discovery.
Questions, paths, anchors and neighbors can return actual reasons, alternatives,
observed work, pending work and uncertainty across their verified owner Sessions.
Graph discovery is Project-scoped and needs no native binding or Session switch;
it does not replace the selected Session's entry or current P2 direction.

Small fitting `workContent` is usable directly in short results. Single-work
results may include their complete large reason beside navigation nodes, while
large multi-original results disclose omitted content and original text ranges.
Inspect `workContentCoverage.partial` before treating a displayed value as
complete. `originalExpansion` uses the existing exact reader with one actual
owner and the size needed by its enriched record. Verify returned identity and
digest after expansion; changes since graph discovery remain possible. No extra
save, approval, tool chain or user-authored ID is required for this discovery.

Default CLI/MCP text makes the returned context readable without changing it.
Entry keeps current common direction, the selected Session's valid purpose and
verified checkpoint context ahead of historical work. A short status, actual
owner and historical/partial scope precede each work body; each judgment keeps
its assessment, reason and alternatives together. Original values are not
summarized or cut again by the formatter. Additional fields, including unknown
keys and empty values, retain their own object location. Identity, reference
diagnostics and other residual detail follow the corresponding body; coverage,
omissions and supported expansion remain with the enclosing context.

This body formatter changes default text presentation. Core original values, MCP
`structuredContent`, CLI `--json`, Hooks, selection and proof checks are unchanged.
A complete returned body remains usable even alongside a changed reference or
`sourceFallback`; their presence does not require an automatic reread. Missing
content or a decision depending on current source can still need the disclosed
exact expansion or affected-source check. Historical content grants no current
effect permission, and a truly empty ready entry stays quiet.

Known normal projection flags and their exact historical-scope explanation are
shown once instead of repeated in residual metadata. A complete
`selectedBodyGroups` envelope is not repeated when it exactly matches the groups
already rendered from the returned records. Partial groups, unexpected values,
new fields, owners, original text, reference checks, coverage and exact expansion
remain visible in their own scope. This is text factoring only: neither the
structured/JSON result nor the startup serializer changes, and an unknown
inventory (`originals: null`) is not treated as no history.

### Session, declared work root and authored topics

At meaningful completion, handoff or changed conditions, Lode can retain actual
consumer results, reasons/alternatives and unfinished work through the same two
writers. Optional `workTopics: string[]` supplies authored navigation labels;
it requires neither Product onboarding nor a user taxonomy. Topics alone are not
meaningful work evidence. Absent topics stay absent in normalized originals, so
legacy identities, digests and exact retry bytes remain unchanged. Existing
aggregate record bounds include topic text; no separate label-count gate is added.

Topic-only graph questions can retrieve the same real body as paths, anchors or
neighbors. A label never creates a Product Feature, IMPLEMENTS/VERIFIED_BY edge,
approval, completion or recovery direction. Existing reviewed Product relations
retain their exact revision contracts. Partial graph labels use original
`workContentExcerpts` field/index/ranges, not a silently renumbered topic array.

Default CLI/MCP text groups actual returned bodies by exact Project/Session and
declared root ID **and digest**. Unlinked records stay standalone; nested anchors
are not transitively collapsed. The same label across Sessions/roots never merges
owners, and multiple labels do not duplicate a stored original or its full body.
Reader/entry may include `selectedBodyGroups` referencing the returned record
indices; actual content remains once in `records`. The optional envelope, including
scope/omission notice and serialization overhead, uses only spare record budget.
Fitting bodies are admitted first. Missing group metadata does not mean missing
work; `omittedGroups` counts omitted view groups, not omitted source content.
The existing `max_characters` contract bounds the record/excerpt delivery,
not the complete reader/MCP transport envelope.

Startup derives groups from its actually admitted output records and checks its
complete Host-specific JSON ceiling after optional metadata. Current direction,
purpose, checkpoint and fitting work bodies have priority. No new reads, writes,
selection changes, archive census, mandatory tool chain or save/start/end/ID ritual
is introduced. Historical ended can coexist with an actual result and pending
verification/unknowns; it does not clear either. Native automatic end, ancestry
and live activity are not implemented by this organization. Local fixture and
instruction checks are not proof of actual Host delivery or model compliance.

The self-contained [lode-conversation Skill](../skills/lode-conversation/SKILL.md)
helps explain Lode work, choices, progress and results in the user's language.
It participates in normal implicit Skill discovery, but is not a prerequisite
for Core execution, recovery or authority protections. Local package validation
checks its bundled bytes, not installation or actual Host selection.

Known generated instruction, role and provider-configuration differences remain
visible without blocking intact selected-Session recovery or work-context reads.
Edited or missing projections are never repaired by entry. Their update/mutation
protections remain separate from original identity, digest and lineage checks;
managed original drift, an unclassified managed path, or an unreadable manifest
is not accepted as projection-only drift. No checkpoint is needed for useful
ordinary work context.

An exact healthy by-id Session remains readable when an unrelated default Session
is missing or damaged. Optional Product facts depending on that default are
unavailable, not a prerequisite to continue. Actual default requests, a damaged
selected Session, known duplicate identities or wrong Project ownership still
fail without substituting another Session. Reads do not repair or switch pointers.

### When common direction linkage is unavailable

A missing direction pointer is not an empty direction if an original revision or
recognized interrupted-publication stage remains. Entry labels that common layer
unavailable while retaining independently verified checkpoint and work evidence.
Lode continues independent work without a save, repair or approval ritual. Current
direction-dependent effects and checkpoint CAS remain strict; historical decisions
and next steps cannot replace the missing current constraints or cancellations.
The existing continuation check runs before consuming its one-shot token.

Empty directories with no recognizable original/stage retain the unused-store
behavior. Neither names, timestamps nor a sole revision select current direction.
Reads write no pointer. Complete removal of all traces cannot be distinguished
from a never-used store without additional evidence. Original integrity/path errors
remain errors, not availability exceptions. Sequential observations are not atomic.

The embedded CLI's `metric-status` uses the same Project-only classification as
its MCP peer even after caller selection loss. Existing readiness checks still
apply; the route neither chooses default nor repairs the Host binding.

Short work creates no additional record. Identical selected input reuses its
original bytes; a genuinely separate repeated observation can carry a Lode-owned
occurrence distinction. Deduplication does not prove that an effect happened.
Different judgments are retained separately, not overwritten by the last writer.
Retry repairs persistence only, never repeats code, provider or external effects.
Abrupt exit before a supported preservation boundary can still lose unsaved work.

## Bounds, originals and uncertainty

### Linked context and saved activity observations

The same two optional evidence inputs accept `workLink: {root, predecessor}`
and `executionObservation: {state, target?}`. Each selector is exactly
`{evidenceId, evidenceDigest}` from a saved original in the same Project and
selected logical Session. States are `running`, `paused`, `ended` and `unknown`.
Lode supplies these internally, only when useful at the existing preservation
boundary. No separate start/end/save call, user ID form or approval is required.
An observation alone may be meaningful; a link alone is not selected work content.

The root is a declared first-retained anchor, not proof of the actual beginning
of the work. The predecessor must be that exact root or an existing original
declaring it. A previously linked original can serve as a new anchor without
erasing its earlier provenance or merging the contexts. New writes validate the
exact endpoints; identical retry first reuses its intact original, even after an
endpoint or source disappears. An absent extension leaves legacy normalized
bytes, identity and protocol unchanged. No migration or activity registry exists.

These are observations of saved notes, not execution-attempt identities. Several
states about one exact target coexist as history; time and predecessor select no
current winner or execution conflict. An `ended` observation about E1 cannot close
a later E3, sibling, all executions mentioned in E1, pending issue or required
review. Failure/cancellation is not success. Unscoped observations do not qualify
another note. Current live state, unsaved restarts and native Session termination
remain unobserved. Nothing is deleted, hidden, reconciled or replayed.

For default reads, `selectionRole` distinguishes recent, explicitly cited
and declared-root bodies. `savedActivity` preserves incoming historical state
sets, bounded exact qualifier selectors/counts and relation availability. Its
own observation remains in original `content`. The separate `organization`
notice explains historical—not live—scope once. `organization.scope` labels counts
of the actually returned source originals, not a whole-history organization census.
Incoming qualifier counts cover the known producers actually verified in the request. Missing/changed relations affect
only that view; a failure actually detected on selected reread also qualifies
dependent overlays, endpoint diagnoses and typed references in the same response.
All known incoming producers for a displayed target receive canonical self/owner
and exact-target checks, not merely a prefix bounded by the returned record count.
An incoming-only producer does not recursively require its unrelated links,
generic references or its own incoming producers. A non-body producer changed after
its check is not necessarily read again; the retained projection is a historical
observation at that check, not proof that its bytes remain intact at return.
Actual bodies and directly used declared endpoints still receive fresh checks.
Observed later failures take precedence; unobserved changes and ABA remain outside
the guarantee. Exact-ID/page reads add no hidden ancestors or qualifier search;
uninspected endpoints/qualifiers are not declared absent or terminal.

The default uses recent seeds, one-hop explicit same-Session work-artifact
citations and their declared roots. It interleaves recent → cited → root, keeps
at least half the available slots for recent/fallback selection and deduplicates
original bodies. With one slot only recent work is returned; with two, the cited
body precedes the optional root. This is a bounded display allocation, not a
semantic eligibility test. If a large anchor cannot fit, recent results and
pending work remain eligible. Reference `digest` hashes file bytes and is not
the original's `evidenceDigest`. Citation content is the actual saved judgment,
not a generated summary or a path presented as recovered reasons.

Extra related body-expansion attempts are bounded by `maxRecords`, including failed
or oversized attempts. That bound does not cap unknown-original verification or
necessary direct endpoint checks. Incoming producers are not all reread before
each displayed target. Proof metadata is retained for deduplication; verified
oversized candidates can supply separate partial excerpts. Selected/related bodies have bounded retention,
not full-history retention. Deferred related expansion and unique budget-omitted
original counts are separate and are not added together. The recent/related/fallback
policy also applies without linkage extensions: an unrelated old extension cannot
switch the slot policy. Plain history fills unused slots newest-first. Explicit
page/cursor behavior is unchanged.

Work originals live in the selected Session's `work-evidence/` directory.
There is no indispensable index or cache. Default entry/read fixes the matching
names/types in that directory. Optional navigation in the existing graph index
can supply historical order and observation-target hints; it contains no work
body or current-validity verdict. Names without usable hints are canonically
checked and merged in the same request before selection. Missing, legacy or
unusable index data falls back to canonical inspection of the discovered set,
without repairing the index, requiring a refresh or interrupting ordinary work.
Actual body candidates and directly used declared root/predecessor/observation
endpoints still receive fresh checks. A valid original contradicting an observed
historical hint causes one canonical fallback over that fixed discovered set,
not rejection as corrupt; later failures between current checks remain failures.
Candidates are considered newest-recorded first, with
evidence ID breaking equal-time ties. The default returns at most eight unique originals, as full records or excerpts,
without judging semantic relevance, sufficiency or current authority. Corrupt or
oversized candidates do not prevent later fitting work from being considered.
There is no automatic pruning, silent deletion or mandatory whole-history audit.

Default `coverage.originals` counts the fixed discovered ID set, whereas
`coverage.inspected` counts its unique originals actually attempted by canonical
verification in this request, including conclusive read/JSON/verification failures.
Historical hint-only originals are not current `coverage.valid` originals.
`omissions.uninspected` is their difference, not a body-budget rejection. For
example, forty independent fitting originals with normal hints can return eight
bodies with eight inspected/valid and thirty-two uninspected; the same originals
with no/legacy index are forty inspected/valid with zero uninspected. Both have
zero `omissions.byBudget` when no actual body admission was rejected.
Neither result proves full body delivery, semantic sufficiency or latest-at-return
state. A later observed failure reclassifies the same ID once. An endpoint first
appearing after directory discovery may be verified as an exact proof-only dependency, but it is not
added to this response's discovered/body set or counts. The next request can
discover it normally. `nextAfterEvidenceId: null` means no default ID-page cursor.
When originals remain uninspected, or valid originals outnumber included bodies,
existing `work_context_partial`
reports partial delivery, not recovery failure, an error or a user-action gate.
Useful exact expansion remains optional; no automatic full audit is required.
Known `evidenceIds` still expand exact originals without enumerating the Session
inventory: `coverage.originals` and `omissions.uninspected` are `null`, and
`nextAfterEvidenceId` is `null`. Inspected counts describe the deduplicated request,
not the Session total. Empty exact results describe only those requested IDs,
not absence of Session history. An explicit non-null
`afterEvidenceId` keeps the earlier lexical ID inspection-page behavior (up to
512), including its continuation cursor and within-page time ordering. This is
not a global time-order cursor or a complete ID-discovery interface. Its numeric
`coverage.originals` remains the discovered inventory size; an exhausted page
describes that page, not absence of Session history. Text stays quiet only for
observed numeric `coverage.originals` equal to `0`, not unknown inventory.
Bounded omission samples do not expose every omitted ID.

To begin that lexical enumeration without inventing an ID, explicitly request
`scanEvidence: true` (MCP `scan_evidence: true`, CLI `--scan-evidence`). The first
page returns its real `nextAfterEvidenceId` and `enumeration.next` arguments for
one subsequent request. Failed or oversized originals count as examined and do
not stall the cursor. Advancing does not reread earlier-page bodies. Page
membership is observed per request; insertion before a cursor can remain unseen,
and a last page is not a whole-history completeness or direction claim. This
optional read does not change default recent selection, exact-ID reads or P2.
The explicit scan can stop before 512 originals when body capacity and the
existing 32 omission/failure selector slots fill. Every examined original has
either its full body or an exact ID in the returned lists; the next frontier
does not skip undisclosed IDs. Admission is lexical in this new scan mode.
Legacy `afterEvidenceId` without the scan flag retains its existing page rules.
Todo arguments request their separate projection; the scan flag alone does not
add an independent Todo-history scan.

Historical hints are replaceable P4 metadata, not a current archive census.
An unselected same-name external restoration, a plausible incorrect rank or an
unobserved false-null observation target can remain unseen. Known incoming states
are not all possible states, and verified direct relations do not prove a globally
acyclic archive. Current purpose, common constraints/cancellation, P2 and effect
authority remain separate. No automatic audit or new user mode is required.

Directory discovery still examines all matching names/types. Compact metadata
remains O(N) and ordering O(N log N); reading/decoding/parsing the whole existing
Project index adds cost proportional to its bytes, entries, dependencies and
navigation rows, including other Sessions/layers. With usable hints, original I/O
depends on unknowns, actual body attempts, direct endpoints, known incoming
producers and generic references. Missing hints, fan-in, oversized fallback or
observed hint contradictions can still require all N originals. This is not a
universal latency improvement or freshness guarantee. Normal writes maintain
optional hints through existing index publication; full refresh and index growth
retain their own verification/serialization costs. Bounded selected/related
bodies and compact proof metadata are retained, not the entire original body set.
Reference checks can skip bodies already known not to fit. Each generic reference
may still temporarily read up to 16MiB.
Incoming counts/state sets use request-local aggregates; failed qualifier removal
does not walk its full history again. Bounded qualifier-list materialization and
record-array serialization still cost work proportional to the displayed data.
Within one read request, the existing read context reuses observed raw reference
bytes or read failures; each descriptor still receives its own digest, kind and
owner checks. The 128MiB retention limit is not an admission gate: outside it a
valid reference falls back to the existing bounded read. No verdict or parsed-JSON
cache is added. Fresh selected-original rereads and the final owner/direction
basis check remain separate observations, and later detected failures take
precedence over earlier success. A new request observes the files again.
Unknown inspection, fresh body attempts (including prepared but unreturned bodies),
direct endpoints and incoming producers can overlap on the same original; these
roles are not a simple sum or an upper bound on file I/O. Generic reference
enrichment may read work-original paths again. Fitting fallback can approach N.
The related body-expansion bound does not cap those proof/reference reads.
Normal hinted reads do not traverse every unobserved predecessor merely to audit
lineage; existing cycle defenses apply to actually observed metadata, and no/legacy
index fallback retains its full-discovered-set defense. This is a sequential view of
the discovered set, not atomic latest-at-return: records added after enumeration
may be absent. No mandatory index, lock, write or service is added.

With full records only, `max_characters` retains the actual
`JSON.stringify(records).length` contract after reference enrichment. When partial
fields are delivered, it counts `JSON.stringify({records,recordExcerpts}).length`,
including the excerpts' selectors, field/group coverage and expansion metadata.
The separate context envelope and independent Todo projection remain a different
scope. The default is 32,768 UTF-16 code units, not UTF-8 bytes, tokens or semantic
sufficiency. Even the minimum budget of two admits zero bodies without an error
or hidden excess; bounded outer coverage discloses the omission.

`recordExcerpts` are P4 views, never shortened `records[].content`. Each `source`
retains the exact Project/Session/evidence ID/digest. `fields[].path` preserves the
original field and array index; a partial string declares `range.unit` as
`utf16-code-units`, with exact start/end/total and grapheme-safe boundaries.
Judgment/task fragments retain their group fields and original association.
`emptyValues` factors explicitly present empty/null values without erasing them.
Small complete structural units are attempted before long prefixes; output order
stays original. This packing is not a model importance or approval judgment.
Coverage states which fields/items/conditions may be missing; the existing exact
read expansion retains its bounded arguments. Exact-ID and explicit page reads
keep full-original semantics and their original errors.

Default unavailable details are sampled up to 32 entries. `coverage.unavailable`
counts unavailable originals within the inspected set, and
`omissions.unavailableDetailCount` is that total minus the displayed sample.
`coverage.valid` includes successfully inspected originals that were never offered
as bodies, proof-only relation/qualifier originals and returned bodies, less
observed later failures. `omissions.byBudget` counts only canonical-valid originals
actually offered complete-body admission and rejected by record or enriched character
budgets; it does not count every undisplayed or proof-only original. Thus
`coverage.inspected = coverage.valid + coverage.unavailable` and
`coverage.included <= coverage.valid`, but default
`coverage.valid = coverage.included + omissions.byBudget` is not guaranteed.
Unique inspected originals are counted once even if reread.
`coverage.included` counts complete records; `coverage.excerpted` counts separate
partial originals. A partial original can still occur in `omissions.byBudget`
because its full body was not delivered; do not add these as disjoint originals.
An original changed or lost on reread becomes unavailable, not a mixed old-order/
new-body result. Explicit page and exact-ID reads retain their bounded detail
range. Body and diagnostic omissions are separate; no empty sample proves absence.

References preserve exact path, byte digest and source/artifact kind. Matching
bytes are not semantic freshness; another Session's artifact is evidence, never
an imported goal or approval. Changed/missing sources are disclosed, and a
path/digest alone is not recovered content. One corrupt original is excluded
without blocking valid records, P2 recovery or independent work. A detected P2
or common-direction change during entry discards that mixed context and asks
Lode to reread only the dependent observation. Sequential reads are not an
atomic snapshot and cannot detect every ABA change.

## Host support without identity guesses

`createSessionHostAdapter` is a trusted embedding-Host API. The Host obtains
the real native caller and, for children, a verified distinct agent identity.
Its declared `select` operation validates an exact logical Session and
compare-and-swap revision, then registers only P5 linkage outside project Canon.
A pending selection survives interruption as unresolved, not the old/default
route. After restart the public adapter reads this linkage; its
`resolveSessionContext` supplies the existing per-request MCP resolver.
Native IDs are hashed for lookup and never become canonical Session identity.
Read-only calls produce no claim or receipt. Explicit sharing and default
selection are choices, not latest-time/name/sole-candidate guesses.

Selection persistence failure does not undo a successful current explicit request.
The result remains usable with its exact logical route, while future linkage is
unconfirmed. Repair only that linkage. If storage fails before any intent is
durable, a restart cannot discover the lost attempt: the Host must not claim
lossless continuity from unwritten state.

The bundled `scripts/session-host-hook.mjs` separates optional lifecycle observation
from startup projection. Its command may retain bounded native event evidence in
the Host-local P5 `native-observations` namespace; this never changes the Project,
an existing selection binding or recovery direction. The pure `sessionStartContext`
reader looks up an already registered binding and returns bounded read-only context
before MCP needs to be ready, without saving notes or inferring direction. It does
not parse transcript bodies; the separate optional ancestry observer can read only
an exact supplied Codex session metadata header. Large startup direction is
explicitly marked for original expansion, not silently cut.

Startup includes the selected Session's current `sessionPurpose` even without a
checkpoint, separately from historical checkpoint purpose and decisions. It also
retains an explicitly reported current-direction availability diagnosis; an
unavailable direction is not the same as a never-recorded null direction. The
final JSON context, including coverage, omissions and expansion advice, has one
Host-specific delivery budget rather than a second common 7,000-character crop.
Claude uses at most 10,000 UTF-16 code units, conservatively following its
[documented per-string ceiling](https://code.claude.com/docs/en/hooks#add-context-for-claude).
Codex uses at most 32,768 UTF-16 code units for the **complete** output: a finite
local resource policy reusing the default work-reader size, not an optimal value,
Host token/window limit, or proof that P2 inputs are bounded. The packaged Codex
handler uses numeric `additionalContextLimit: 0` alongside that strict emission
guard, following the [documented full-output option](https://learn.chatgpt.com/docs/hooks#large-hook-output).
The old approximate 4,096-token setting could spill even a character-bounded
multilingual result. Installed Host support and actual model receipt remain
separate verification; characters, UTF-8 bytes and model tokens are not equivalent.
Current direction/purpose/checkpoint inputs themselves have no text-length cap;
the existing 32,768-character work read covers its full/partial P3 delivery only.
Exact current common direction, Session purpose and the
latest selected checkpoint's purpose/decisions/position/next-result fields take
priority over optional prose, coverage detail, ID samples and P3 history. The
checkpoint's recorded approvals/next steps still grant no current effect authority.
Only current content that cannot fit its minimal truthful envelope is explicitly
omitted whole, never shortened into different direction. Existing entry/work reads
expand needed originals using the same exact Session route; normal startup does
not require a follow-up read. Only if optional reductions cannot fit an
unusually long root is its rendered path omitted with the original Hook cwd
identified as its source. None of this changes selection, writes a binding or
requires a checkpoint, save, approval or extra routine user step.

For organized history, startup fits the historical-scope notice and first record
together, and always fits each body with its saved-activity overlay. Optional
organization detail cannot leave an old running body presented as live state.
When discovered originals remain uninspected, the existing `scope` also says
that archive hints are historical and only inspected originals were checked,
even if optional detailed coverage must yield to current purpose/P2. Full
coverage or compact source counts retain their actual inspected/included basis;
the shorter notice does not claim a fresh archive scan or require expansion.
Where existing restore supplies `currentExecution`, a separate small axis keeps
its exact status and canonical active/pending-review/required-plan facts. Incomplete
or conflict stays so; a raw pointer is not verified execution. No checkpoint means
no new execution scan. This axis and all history yield to protected common/P2
direction and purpose within the applicable complete-output ceiling. The minimal
canonical execution status remains visible if its optional details cannot fit.

Transport removes repeated wrappers, not authored meaning. Startup
uses compact truthful guidance before admitting any authored block; longer
optional guidance returns only with spare capacity after original bodies.
Common direction keeps its `directionId`, `directionHash` and exact `input`; recovery retains its
checkpoint digest and open review IDs alongside the four original direction
fields. Work `content`, including reasons, alternatives, references, pending work
and unknowns, stays unchanged, with its evidence ID/digest and observation overlay.
`referenceChecks[].referenceIndex` points to the exact matching path/digest/kind
in that content's references; verification status, actual/null owner and exceptional
diagnostics remain. An unpaired descriptor is retained whole, not guessed.
These hashes select verified originals, not the compact projected JSON. Reference
byte matching does not establish semantic freshness or authority. Unavailable or
changed-basis work retains status/reason and expansion even with zero records.
The same pure P4 fitter measures the complete startup JSON, including excerpt
metadata, under each existing Host ceiling. Full work content remains unchanged;
smaller startup capacity can instead carry clearly separate partial excerpts.
Zero full records with excerpts is neither empty history nor complete recovery.
No original, selection, binding, tool chain or user step is added. Protected P2
that cannot fit is omitted whole with dependent-only expansion; omitted
cancellation never means absent cancellation. No local spill
file or automatic follow-up read is created. Actual Host spill/preview behavior
must not be called complete recovery. The guard bounds emitted text, not the
memory required to read already-valid unbounded P2 inputs.

Codex tool Hooks expose the parent's session ID for child agents and cannot
safely register caller selection from that field alone. Codex argument rewriting
also requires an allow decision, so it is not used for routing. No broad Hook
denial, deny/retry normal workflow, permission bypass or global MCP selector is
introduced. Correct explicit requests and independent Project work remain
available after optional binding loss.

The shared state-write policy runs once after router unwrap, before dependent
Session diagnostics. Unset protection applies only to exact-supported Claude
and OpenCode child calls. Codex remains off by default; explicit
`LODE_SUBAGENT_WRITE_GUARD=enforce` preserves its existing known-child behavior,
and explicit off disables this optional Host policy. Catalog `readOnlyHint`
metadata determines protected state writes. Reads, parent/independent work and
ordinary source edits stay available; a rejection is
`SUBAGENT_STATE_WRITE_REJECTED`, never a new user approval ritual or authority
for the parent.

Claude's own local/plugin PreToolUse matchers derive Session/transition, router
and effectful coverage from the actual catalog, including finite supported
aliases and excluding the helper/other servers. Child `agent_id` is combined
with the exact outer tool name, argument digest, `tool_use_id` and actual MCP
`claudecode/toolUseId`. Protected Project-only writes use the same bounded
transient registry without Session/P2/inventory reads or persistence. A
`caller.subagent` bit alone, signal-only fallback, expired/replayed/mismatched
claim or missing native metadata cannot enable default protection. Such paths
are unsupported/unknown, not protection successes or blanket denials.

When explicitly enforced, Codex still recognizes `_meta.agent_id` or
`_meta.subagent`, and a `SubagentStart` observation whose native ID matches
`params._meta.threadId`. Unset/off does not add those optional lookup costs.
OpenCode applies the same policy in the actual awaited before-hook using its
owned server, exact call ID, Project/directory and Session `parentID`. It does
not publish a cross-call child ticket. Ordinary source tools and read-only calls
need no policy Session lookup; missing call ID, unsupported scope, lookup error
or timeout does not assert protection or block independent work. Neither path
is malicious-client isolation or proof of actual installed Host delivery.

### Which operations retain a selection?

Only the existing successful `lode_project_initialize_or_resume` selection is
retained. Initial setup keeps the verified default; explicit resume can share or
separate existing Sessions. Repeating an unchanged choice writes nothing. There
is no extra select/bind tool, user ID form, save ritual or permission decision.
Creating a Session alone, an explicit read, writing evidence/checkpoints for a
different Session, and worker integration do not silently select it for the chat.

Pure bootstrap validation and identity checks precede optional P5 preparation.
The executing request keeps its already verified route while its selection is
pending. Short CAS sections do not lock the whole operation. Settlement cannot
overwrite a newer intent. A proven pre-effect failure may restore the verified
prior choice; generic error, cancellation or timeout does not prove no effect.
Unknown outcomes and restart without a live ownership ticket retain pending
uncertainty. Host persistence failure never changes the original Core outcome or
replays its effect. Bindings and caller metadata remain P5, not P2 direction.

One MCP process may receive multiple callers: every request uses its own outer
transport metadata, not a last-caller selector or arguments named `_meta`.
Embedding Host resolvers retain precedence. A never-bound caller keeps existing
default semantics without read-side writes. Known lost/pending/corrupt linkage,
including a missing binding in an existing namespace, never substitutes default.
Complete deletion of that namespace cannot prove its unwritten/deleted history.
Legacy transport without caller metadata does not claim automatic continuity;
once native metadata is observed, its loss affects only dependent calls. Valid
explicit requests and independent Project work remain usable.

### Claude request correlation, without another permission gate

Bundled PreToolUse Hooks target only this plugin's Session-dependent tools and
generic routers, on their exact local or plugin-scoped MCP server. The Hook
sends the real `session_id`, distinct child `agent_id`, `tool_use_id`, outer tool
name and original outer arguments to that same server. The actual ordinary MCP
call supplies outer `claudecode/toolUseId`; the in-memory registry verifies its
exact argument digest before unwrapping a router and resolves that caller only.
Normal model calls, router calls to the helper, nested fake metadata and
unexpanded templates cannot prepare this linkage on the observed stock transport.
This is a verified stock-transport seam, not arbitrary-client authentication.

The helper returns `{}` and never supplies `permissionDecision`, `updatedInput`,
logical Session, approval or P2 direction. Native permission remains Host-owned.
Direct independent tools add zero RPCs; a generic router adds one internal Hook
RPC even for an independent inner operation, where preparation immediately does
nothing (no registry, Session/P5 read, graph scan or original write). No new user
question, binding form, Run, Capsule, save receipt or daemon is required.

Pending correlations expire after ten minutes and are capped at 1,024 entries;
active entries cannot be evicted. Exact pending retry converges without extending
its lifetime; conflicting/active reuse cannot replace another caller. Claim release
is in `finally`, and transport close clears the cache. Denied calls may leave a
pending memory entry until sweep/close, not a durable per-call artifact. The
bounded spent cache is not durable replay protection or an execution lease.
Cold Claude metadata without a matching Hook fails only dependent automatic
routing, never guesses default. Valid explicit routes and independent work remain
usable; a new Project may initialize without claiming native linkage. Missing
Hook activation, expiry and optional storage loss are diagnostic gaps, not a
reason to repeat completed effects. Resume needs the same native chat, project
and operational binding storage; cross-machine continuity is not implied.

Official contracts: [Codex Hooks](https://learn.chatgpt.com/docs/hooks) and
[Claude Code Hooks](https://code.claude.com/docs/en/hooks).
Source/command fixtures prove these local contracts, not installed Hook trust,
actual provider invocation or model understanding. Installing a package does not
prove its Hook ran; real activation and account/model tests are separate.

## Path bases and existing Projects

Project-internal references use validated Project-root-relative `/` paths. Generated
Markdown `relativePath` starts at the published root; each href starts at its
containing document. A `../` document link does not permit `..` in a durable selector.

Runtime `project_root`, stored `projectRoot`, installation `pluginRoot` and root-derived
identities remain bound to the verified absolute root and actual Session owner. New
Projects use `.lode/`; existing `.head/` records and exact selectors stay unchanged.
These are existing path contracts, not workspace relocation or automatic repair.


The read-only `sessionStartContext` renderer awaits the selected Host adapter and local snapshot reads before formatting. Codex/Claude command Hooks and the OpenCode context callback consume the completed value; an unresolved Promise is never presented as empty context. This changes no Session selection or P2 authority.
